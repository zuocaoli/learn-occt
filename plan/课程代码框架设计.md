# 六个月 OCCT 课程代码框架

## 1. 目标与约束

为[六个月学习计划](CAD几何建模引擎.md)提供同一套实验底座。每周复制完整框架，独立构建、运行、修改和调试；框架源目录只用于复制，各周不会引用它或其他周产物。

- 工具链固定为 **Clang + CMake + Ninja + clangd**。
- 项目语言标准允许 C++20 及以上；模板明确选用 **C++23、`import std;`**，不提供 C++20 兼容实现。
- GUI 使用 **Qt Widgets 6.11.2 + OCCT AIS/V3d/OpenGL**；当前适配 Linux X11/XWayland。
- OCCT 公共安装是 `几何引擎/occt`，当前版本 `8.1.0 dev1-3d097a03`。共享的是第三方依赖，各周的课程代码和构建结果完全独立。
- 框架提供完整实验底座，算法按周添加；不建立一套替代 OCCT 的几何类型或统一建模算法封装。
- 本阶段只交付[可运行模板](../template/week-template/README.md)，不预先创建 24 周课程。

## 2. 目录与依赖方向

模板位于 `几何引擎/template/week-template/`；复制后的周目录为 `几何引擎/monthNN/weekYY/`。二者深度相同，默认 OCCT 路径均为 `../../occt`。

```text
weekYY/
├── README.md                本周五题、练习和验收；模板 README 则说明复制方法
├── CMakeLists.txt / CMakePresets.json / run.sh
├── .clangd / .clang-format / .vscode/
├── main.cpp                 GUI 入口，先判断 --headless
├── console.cpp              完全不依赖 Qt 的入口
├── framework/
│   ├── experiment.*         参数、实验契约、运行上下文
│   ├── inspect.*            拓扑统计、对象说明和有效性检查
│   ├── artifacts.*          BREP 读写、报告与阶段输出
│   ├── command_line.*       命令行解析及无窗口执行
│   ├── runtime_config.hpp.in
│   └── ui/                  Workbench 与原生 OCCT Viewport
├── experiments/             本周直接调用 OCCT 的实验
├── tests/                   标准库核心检查、Qt 适配测试、真实视窗测试
├── tools/README.md          版本、构建、IDE 和调试说明
└── build/                   本周独有，忽略提交
```

`geometry_core` 包含运行、观察、文件、命令行及实验，依赖标准库与 OCCT Modeling targets。`geometry_ui` 依赖核心、Qt Widgets、OCCT Visualization 和 X11；`demo`、`console-demo` 复用核心。GUI 可整体关闭，核心测试无需 Qt。

框架内部采用普通头文件/实现文件分离；实现文件开头先写 `import std;`，再包含 OCCT、Qt 和公开 C++ 类型的头文件，避免当前 clangd 的标准库定义冲突诊断。没有跨周 C++ 模块、脚本或库。

## 3. 实验契约与数据流

### 参数与实验

`Experiment` 包含实验标识、标题、参数定义和执行函数，通过 `make_experiments()` 静态注册。新增源文件及所需 OCCT target 同时登记在本周 CMake 中，不使用动态插件。

`ParameterSpec` 定义参数键、标签、默认值、范围、枚举选项和说明；`ParameterValues` 保存实数、整数、布尔或枚举字符串。GUI 自动创建对应控件，命令行使用 `--param key=value`。

参数必须完整、键与类型匹配；实数有限；整数不接受小数；数值满足声明范围；布尔只接受 `true/false`；枚举值在 `choices` 内。入口校验之外，壁厚、半径和自交等几何条件由实验解释和处理，不用统一的容差常量掩盖。

### 运行上下文

执行接口：

```cpp
void experiment(const ParameterValues& values, RunContext& run);
```

- `run.publish(StepResult{...})` 记录阶段，可包含多个具名 `TopoDS_Shape`、辅助图元、测量和诊断；`run.log()` 记录过程说明。
- `Primitive` 支持点、线段和带箭头向量，使用模型坐标；零长度向量不绘制。
- `Diagnostic` 包含级别、说明和可选问题子形状。检查器使用 BRepCheck 状态名称并记录关联形状；点选诊断可查看和突出显示。
- `RunContext` 保留阶段、日志、执行状态和错误；运行器捕获 OCCT、标准及未知异常。

结果发布之后按只读处理。`TopoDS_Shape` 的普通赋值共享底层数据，不代表深复制；原地修复前由实验显式复制输入，以保存可比较的旧模型。初始刚体变换实验通过 OCCT 的复制选项保留输入。

**执行成功与模型有效是两项判断。** 故意产生缺陷的实验可以执行成功并输出无效模型；检查错误不会自动丢弃模型。执行异常则标为失败，已经发布的阶段和输入仍可导出。

每次运行重建上下文、树和视窗内容，防止把上次模型误认成本次结果。GUI 保存实验与实际参数快照；随后修改面板或切换实验，不改写已有结果的导出信息。

### 观察与选择

`inspect()` 按拓扑身份去重统计顶点、边、面、实体；共享边不能按遍历出现次数累计。体积只针对包含实体的模型报告，低维对象的体积显示为 0，不据此判断几何为空。

对象说明包含拓扑类型、方向、位置矩阵，以及顶点位置、边/面容差、基本曲线/曲面类型和检查结果。进一步的 pcurve、UV、连续性和操作历史留给对应周实验展开。

树按“阶段 → 模型 → 直接拓扑子形状”组织，按需展开，保留方向和位置。视窗选择回传 `TopoDS_Shape`，树在当前阶段查找对应对象；树选择通过独立高亮展示子形状。去重统计与树中的使用实例承担不同职责。

阶段号、对象号、树节点号只在当前运行有效；不实现持久拓扑命名。研究 `Modified/Generated/Deleted` 时，由该周保存实际算法返回的形状关系，不依赖树编号。

## 4. 界面、输出与运行环境

顶部实验/运行/重置/导入导出/视图控制，左侧参数和拓扑树，中央三维视窗，右侧对象说明，底部测量日志与诊断。

- 左键选择，右键旋转，中键平移，滚轮缩放；支持标准视角、线框/着色、对象显隐及整体/顶点/边/面选择。
- 原生 QWidget 持有窗口，OCCT 持有 OpenGL 渲染对象。`AIS_ViewController` 处理输入；逻辑坐标转换到设备像素后传入 OCCT，原生尺寸在 resize 与 paint 阶段同步。
- AIS 对象留在显示层，不进入核心结果。辅助图元不参加模型选择。
- 初始执行采用 GUI 主线程同步模式，运行期间禁止重复执行；不预先引入线程和取消状态机。

无窗口入口在创建 QApplication 前分流；也可关闭 `GEOMETRY_BUILD_GUI`，完全不构建 Qt/视窗目标。`--help` 和 `--list` 同样不连接显示器。

导出到不存在或空目录，保留原案例；报告包含版本、状态、参数、阶段名称、对象编号、测量、辅助图元、诊断和复现命令。BREP 以 `step-N-object-M.brep` 命名，关联问题对象另存为诊断 BREP。名称不参与文件路径拼接。

`--input` 或 GUI 文件选择加载 BREP 并重新检查；其复现命令引用输入文件，复制案例时需要保留输入。当前不保存 GUI 布局、AIS 显示状态，也不提供 STEP、STL 或完整文档序列化。

当前 OCCT 动态库没有自身 RUNPATH。CMake 为 executable 设置包含 OCCT 库目录的 DT_RPATH，以查找直接和间接依赖；配置生成资源路径，应用补齐未设置的 `CSF_*`。不全局改写用户环境，也不将 OCCT 库复制到每个 week。

## 5. 六个月扩展安排

| 月份 | 每周编写的实验 | 复用或增加的框架能力 |
|---|---|---|
| month01 | 坐标/变换、采样、拓扑遍历、共享边、方向与 pcurve | 初始框架、图元、统计、选择与对象说明 |
| month02 | Wire/Face、拉伸、旋转、扫掠、放样、连续性和缝合 | 复用多模型阶段、参数和检查 |
| month03 | 投影、求交、分割、裁剪与周期接缝 | 增加二维参数域视图；核心记录仍与 GUI 分离 |
| month04 | 布尔、操作历史、相切/间隙案例、倒圆角 | 实验中保存历史映射；复用阶段/诊断 |
| month05 | 尺度/容差、缺陷分析、针对性修复和后续可用性 | 复用问题定位、BREP 读写和前后测量 |
| month06 | 法兰管件、参数变体、成功/失败复现和源码跟踪 | 复用全流程；切换带符号 OCCT 安装 |

初始模板是“矩形底面 → 长方体 → 平移 → 旋转”，连接此前矩形案例；各类小实验选用合适形状，最后综合成法兰管件。不预建 24 周算法 API，不引入 OCAF、特征树、表达式、撤销重做、跨课程依赖或动态插件。

## 6. 验收与维护

具体命令见模板 [tools/README.md](../template/week-template/tools/README.md)。

- 核心：默认长方体 8 顶点、12 边、6 面、1 实体，体积约 24000；长度 60 时约 36000。三个阶段均有效，刚体变换不改体积。
- 参数：覆盖范围、非有限数、未知键、类型、整数、布尔和枚举；GUI/CLI 共同执行相同实验。
- 案例：BREP 往返、读写错误、防止覆盖；异常后保留阶段；无效线框产生关联对象诊断且不被丢弃。
- 适配：Qt 离屏测试验证参数、重置、实际参数快照、树与选择同步、失败后清空旧模型。
- 真实视窗：Xvfb 下测试 GLX、非空图像、鼠标选面和树联动、窗口尺寸、旋转/平移/缩放/显隐/线框，以及 1×/2×设备像素比例。截图留在本周 build。
- 副本：临时复制两份完整周源码，各自配置、构建、运行；修改一份默认参数后另一份结果不变，编译数据库只包含自身源码。

模板修复不自动同步到已有周副本。需要同步时手工挑选改动，并在该周重新验收。当前 OCCT 为 Release；第 6 月准备匹配源码及带调试符号安装，用 `OpenCASCADE_DIR` 切换并 fresh 配置，不覆盖现有安装。
